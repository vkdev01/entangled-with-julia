Every language has one thing it refuses to apologise for. Python has whitespace.
JavaScript has `==`. Julia has `v[1]` being the *first* element, and it will not be
moved on the subject.

This note is the shortest path from "why is my loop skipping the first item" to
"oh, dispatch is the whole design". Two ideas, one afternoon, zero excuses.

<KeyIdea>
Julia's indexing is 1-based because it was designed by people writing numerical code,
where 1-based maths (`x₁ … xₙ`) is the notation everyone already uses. The language
pays for it with `begin`/`end` and `eachindex`, and you get used to it in about a week.
</KeyIdea>

## Index from one

Vectors, matrices, strings — one rule, no exceptions. Here is the whole story at the
REPL:

```julia title="repl"
julia> v = [10, 20, 30]
3-element Vector{Int64}:
 10
 20
 30

julia> v[1]
10

julia> v[end]
30

julia> v[0]
ERROR: BoundsError: attempt to access 3-element Vector{Int64} at index [0]
```

That `BoundsError` is not a crash, it is a *diagnosis*. Julia tells you the length of
the container and the index you asked for, which is more than most languages bother
with.

Matrices are column-major, so the last index moves down a column, not across a row:

```julia title="basics/matrices.jl"
A = reshape(1:9, 3, 3)   # 3×3 matrix, filled column by column

println(A[1, 1])         # 1   — row 1, column 1
println(A[3, 1])         # 3   — bottom of the first column
println(A[1, 3])         # 7   — top of the third column
println(A[end])          # 9   — last element in memory order
println(A[2, :])         # [2, 5, 8] — a whole row, still 1-indexed
println(size(A))         # (3, 3)
```

```text title="expected output"
1
3
7
9
[2, 5, 8]
(3, 3)
```

<Callout variant="warn" title="Column-major is not a detail">
`A[i, j]` walks down a column. Loops written `for i in axes(A, 1), j in axes(A, 2)`
touch memory in a cache-friendly order; the same loop with `i` and `j` swapped is
correct and several times slower. Same output, different speed.
</Callout>

## begin & end

The compensation for losing zero is that Julia hands you symbolic bounds. You never
write `length(v) - 1` again:

```julia title="basics/bounds.jl"
v = [10, 20, 30, 40, 50]

println(v[2:4])        # [20, 30, 40]
println(v[begin])      # 10  — same as v[1]
println(v[end - 1])    # 40  — no arithmetic gymnastics
println(v[begin:2])    # [10, 20]
println(eachindex(v))  # Base.OneTo(5)

# the loop you should actually write
total = 0
for i in eachindex(v)   # works for arrays, ranges, OffsetArrays
    total += v[i]
end
println(total)         # 150
```

```text title="expected output"
[20, 30, 40]
10
40
[10, 20]
Base.OneTo(5)
150
```

`eachindex` is the portable answer. If a package ever hands you an array that starts
at 0 — `OffsetArrays.jl` does exactly that, on purpose — `eachindex` follows it and
your hard-coded `1:n` does not.

## Dispatch in 12 lines

Now the part that makes Julia Julia. Functions do not belong to types; types are
arguments that pick *which* method runs. Same name, different shapes, decided at call
time by the actual types.

```julia title="basics/dispatch.jl"
abstract type Shape end

struct Circle <: Shape
    r::Float64
end

struct Rect <: Shape
    w::Float64
    h::Float64
end

area(c::Circle) = π * c.r^2
area(r::Rect)   = r.w * r.h
area(shapes::Vector{<:Shape}) = sum(area, shapes)   # generic, built on the two above

shapes = Shape[Circle(1.0), Rect(2.0, 3.0)]

println(round(area(shapes[1]); digits = 4))   # 3.1416
println(area(shapes[2]))                      # 6.0
println(round(area(shapes); digits = 4))      # 9.1416
println(methods(area))                        # 3 methods, one name
```

```text title="expected output"
3.1416
6.0
9.1416
3 methods for generic function "area" from Main:
 [1] area(shapes::Vector{<:Shape})
 [2] area(c::Circle)
 [3] area(r::Rect)
```

Ask the compiler which one it picked — this is the single most useful debugging tool
in the language:

```julia title="basics/which.jl"
using InteractiveUtils

@which area(Circle(1.0))
# area(c::Circle) in Main at basics/dispatch.jl:17

@code_typed area(Rect(2.0, 3.0))
# CodeInfo(...) — no dynamic dispatch, no boxing, just arithmetic
```

<Callout variant="tip" title="Dispatch is not overloading">
In C++ or Java you pick a method by the *static* type at the call site. Julia looks at
the *runtime* types of every argument. That is why `area.(shapes)` — broadcasting over
a heterogeneous vector — still calls the specialised method for each element, at
native speed.
</Callout>

## Why the compiler cares

Multiple dispatch is not a convenience feature bolted onto a fast language. It is the
mechanism that makes the fast part possible: when `area(c::Circle)` is called, Julia
knows every type involved, generates a specialised version of the method for exactly
that signature, and caches it. The second call to that signature is free.

```julia title="basics/specialise.jl"
f(x) = x^2 + 1

f(3)        # compiles a method for Int64  → 10
f(3.0)      # compiles a method for Float64 → 10.0
f(3 // 1)   # compiles a method for Rational{Int64} → 10//1

# three signatures, three native methods, one line of source
println(length(methods(f)))   # 1 — but three compiled specialisations
```

This is why the first call in a fresh session feels slow and everything after it feels
impossible. It is also why the `method cache` box in the diagram on the right is the
most important box on the page.

<Gotchas>

- **`v[0]` is a `BoundsError`, not `nothing`.** Julia would rather stop you than return
  a silently wrong value. Use `v[end]`, `first(v)`, `last(v)`, or `get(v, 0, nothing)`
  when you genuinely want a default.
- **`1:3` is a range, not a vector.** It is lazy, allocation-free, and prints as `1:3`.
  Call `collect` only when you truly need a `Vector`.
- **Off-by-one bugs move, they do not disappear.** Code ported from Python usually
  needs `for i in 0:n-1` rewritten as `for i in 1:n` — and the `n-1` becomes `n`.
- **`methods(f)` counts methods, not specialisations.** One method can compile into
  dozens of native versions; that is the entire point of the type system.
- **A `Vector{Shape}` is slow; a `Vector{Circle}` is fast.** Abstract element types
  force a dynamic lookup per element. Prefer concrete element types, or accept the
  cost knowingly.
- **`begin` inside a string literal is interpolation-adjacent territory.** In `"$(begin 1+1 end)"`
  it works; in prose it is just a word. Nothing breaks, but your reviewer will ask.

</Gotchas>
